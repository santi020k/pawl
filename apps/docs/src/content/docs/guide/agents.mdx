Pawl was built for code that an agent writes and a person reviews. Two things make that work: output the agent can act on, and a ratchet the agent cannot argue its way past.

## Output for agents

```sh
pawl check --changed --format agent
```

One JSON object per line, errors first, and nothing at all when there is nothing to do. Where pawl knows how to fix a finding, the line carries a `fix`. Here is one, spread over several lines:

```json wrap
{
  "file": "src/api.ts",
  "line": 1,
  "rule": "biome:correctness/noUndeclaredDependencies",
  "message": "Dependency made-up-package isn't specified in package.json.",
  "fix": "Check that the package exists and is the one you mean, then add it to package.json."
}
```

Here is a real run, after an agent added a file that imports a package that is not installed, uses `any`, compares with `==`, and hides one finding behind a `biome-ignore` comment:

{agentRun && <Terminal lines={agentRun.lines} title="agent run" />}

`--changed` limits the run to files changed against `HEAD`, plus untracked ones, so the agent hears about its own work only. In a folder that is not a git repository it checks every file. `--format json` prints the whole result as one document instead.

## Disable comments fail

A file that gains `biome-ignore`, `eslint-disable`, `oxlint-disable`, `@ts-ignore`, `@ts-expect-error` or `@ts-nocheck` fails with `pawl/no-new-disable`. Switching a check off is not a way past it; fixing the code is. Existing disable comments are part of the [baseline](/guide/ratchet/), so this applies only to new ones.

## Set it up

```sh
npx @santi020k/pawl init --agents
```

`--agents` sets up three things: a hook for each agent the repo uses, instructions every agent reads, and a skill.

### Hooks that fix each edit

After every edit an agent makes, its hook runs:

```sh
npx pawl fix --hook
```

Pawl reads the files the agent just edited from the hook's input, applies the safe fixes and formatting to those files and no others, and checks them. What is left goes back to the agent in the shape its tool reads, as `--format agent` lines under a line that says what pawl did. With nothing left, the hook prints nothing.

| Agent                                  | File                      | Written when the repo has                                                  | What the agent hears                                          |
| -------------------------------------- | ------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Claude Code                            | `.claude/settings.json`   | Always                                                                     | What is left, next to the result of its edit                  |
| Codex                                  | `.codex/hooks.json`       | A `.codex` folder                                                          | What is left, as developer context                            |
| GitHub Copilot, the CLI and the agent  | `.github/hooks/pawl.json` | `.github/copilot-instructions.md`, `.github/instructions` or `.github/hooks` | What is left, after the result of its edit                    |
| Cursor                                 | `.cursor/hooks.json`      | A `.cursor` folder                                                         | Nothing: Cursor does not read a hook's output back            |

The hook goes in next to any hooks you already have. This is the one for Claude Code:

```json title=".claude/settings.json"
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "npx pawl fix --hook"
          }
        ]
      }
    ]
  }
}
```

Codex matches `apply_patch`, the tool it makes every edit with, and runs a project's hooks only once you trust them: review pawl's in Codex's `/hooks`. Copilot runs its hooks after every tool, so pawl skips the tools that edit nothing. Under Cursor the hook only fixes, and the `AGENTS.md` instructions tell the agent to run the check.

When part of the check cannot run, such as an engine that is not installed, the hook tells you and not the agent: it prints the problem and exits with 1, which the agent's tool shows you and goes past. An agent told that Biome is missing would go and install it.

Older versions of pawl wrote other hook commands, `npx pawl check --changed --format agent` for Claude Code and `npx pawl fix --changed` for Cursor. Running `init --agents` again swaps them for `npx pawl fix --hook` in place.

### Instructions every agent reads

Pawl writes instructions into `AGENTS.md` between `<!-- pawl:start -->` and `<!-- pawl:end -->` markers, so running `init` again updates its block and leaves the rest of the file alone:

```md title="AGENTS.md"
## Code quality

This repo uses pawl. After editing code, run:

    npx pawl check --changed --format agent

It prints one JSON line per problem, each with a `fix`. No output means there is nothing to do.
Run `npx pawl fix` to apply formatting and safe fixes.

Do not silence a problem with a disable comment (`biome-ignore`, `eslint-disable`, `@ts-ignore`).
New ones fail the check. Fix the code instead. Do not run `pawl baseline` to make findings go
away either: it accepts them as they are, and that is for a person to decide.
```

Codex, Copilot, Cursor and most other agents read `AGENTS.md` on their own. Two need a pointer:

- **Claude Code** reads `CLAUDE.md`, not `AGENTS.md`. Pawl adds `@AGENTS.md` to the end of your `CLAUDE.md`, or `@../AGENTS.md` to `.claude/CLAUDE.md`, so Claude Code loads it. Without either, it writes a `CLAUDE.md` that only imports `AGENTS.md`. A `CLAUDE.md` that already imports it, or is a link to it, is left alone.
- **Gemini CLI** reads `GEMINI.md` unless its settings name other files. In a repo with a `.gemini` folder, pawl adds `AGENTS.md` to `context.fileName` in `.gemini/settings.json`, after the files it already lists.

### A skill

Pawl writes a skill, the same file in `.claude/skills/pawl/SKILL.md` for Claude Code and in `.agents/skills/pawl/SKILL.md`, where Codex and Copilot look. An agent loads it when it needs it: what to run after an edit, how to read the findings and the exit codes, how to look up a rule with `pawl explain`, and what not to do, such as adding a disable comment or running `pawl baseline`. Running `init --agents` again updates pawl's copy. To keep a version of your own, delete the line that says pawl wrote it.

## The hook from your own setup

`--hook` works in any agent's post-edit hook, not only the ones `init` writes. It reads the file paths Claude Code, Codex, Copilot, VS Code, Cursor and Windsurf send, and answers each in its own shape: `hookSpecificOutput.additionalContext` for a `PostToolUse` hook, `additionalContext` for Copilot, nothing for Cursor. A file outside the project, a file that is gone, and a payload pawl cannot read all mean nothing to do. `pawl check --hook` reports without fixing.

## Running init under an agent

`init` offers a menu in a terminal. In CI or under a coding agent it uses `auto`, so an agent can set up a repo without getting stuck on a prompt. Add `--yes` to accept the plan without asking.
