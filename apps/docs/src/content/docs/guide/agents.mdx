Pawl was built for code that an agent writes and a person reviews. Two things make that work: output the agent can act on, and a ratchet the agent cannot argue its way past.

## Output for agents

```sh
pawl check --changed --format agent
```

One JSON object per line, errors first, and nothing at all when there is nothing to do. Where pawl knows how to fix a finding, the line carries a `fix`. Here is one, spread over several lines:

```json wrap
{
  "file": "src/api.ts",
  "line": 1,
  "rule": "biome:correctness/noUndeclaredDependencies",
  "message": "Dependency made-up-package isn't specified in package.json.",
  "fix": "Check that the package exists and is the one you mean, then add it to package.json."
}
```

Here is a real run, after an agent added a file that imports a package that is not installed, uses `any`, compares with `==`, and hides one finding behind a `biome-ignore` comment:

{agentRun && <Terminal lines={agentRun.lines} title="agent run" />}

An agent gets this format without asking for it. Pawl knows Claude Code, Cursor, Codex, Gemini CLI and other agents by the variables they set on the commands they run, so a plain `pawl check` from an agent prints JSON lines too, and no command shows an agent colors, spinners or a question it cannot answer. `--format` still picks another format, and `PAWL_AGENT=0` says a person is running pawl. The [CLI reference](/reference/cli/#output) lists the variables.

`--changed` limits the run to files changed against `HEAD`, plus untracked ones, so the agent hears about its own work only. In a folder that is not a git repository it checks every file. `--format json` prints the whole result as one document instead.

## Disable comments fail

A file that gains `biome-ignore`, `eslint-disable`, `oxlint-disable`, `@ts-ignore`, `@ts-expect-error` or `@ts-nocheck` fails with `pawl/no-new-disable`. Switching a check off is not a way past it; fixing the code is. Existing disable comments are part of the [baseline](/guide/ratchet/), so this applies only to new ones.

## Set it up

```sh
npx @santi020k/pawl init --agents
```

`--agents` sets up three things: a hook for each agent the repo uses, instructions every agent reads, and a skill.

### Hooks that fix each edit

After every edit an agent makes, its hook runs:

```sh
npx --no pawl fix --hook
```

Pawl reads the files the agent just edited from the hook's input, applies the safe fixes and formatting to those files and no others, and checks them. What is left goes back to the agent in the shape its tool reads, as `--format agent` lines under a line that says what pawl did. With nothing left, the hook prints nothing.

### A check before the agent finishes

An agent can read what the edit hook says and still finish with errors left. So when the agent stops, a second hook runs:

```sh
npx --no pawl check --hook
```

It checks every file the agent edited in the session, as the edit hook recorded them, and not the rest of your working tree. While new errors are left, it sends the agent back with the list as its next instruction. Warnings do not, unless there are more than the limit allows. Pawl sends the agent back at most three times in a row, and not again when a round changed nothing: an agent that cannot fix a problem would go round in circles. Then the agent stops, and you get one line that says how many problems are left. Once the agent is done, pawl forgets the session's edits, so the next turn starts clean.

| Agent                                  | File                      | Written when the repo has                                                    | After an edit, the agent hears               | When it stops                               |
| -------------------------------------- | ------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------- | ------------------------------------------- |
| Claude Code                            | `.claude/settings.json`   | Always                                                                       | What is left, next to the result of its edit | `Stop`: sent back with what is left         |
| Codex                                  | `.codex/hooks.json`       | A `.codex` folder                                                            | What is left, as developer context           | `Stop`: sent back with what is left         |
| GitHub Copilot, the CLI and the agent  | `.github/hooks/pawl.json` | `.github/copilot-instructions.md`, `.github/instructions` or `.github/hooks` | What is left, after the result of its edit   | `agentStop`: sent back with what is left    |
| Cursor                                 | `.cursor/hooks.json`      | A `.cursor` folder                                                           | Nothing: Cursor does not read it back        | `stop`: what is left, as the next message   |

The hooks go in next to any hooks you already have. These are the ones for Claude Code:

```json title=".claude/settings.json"
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "npx --no pawl fix --hook"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "npx --no pawl check --hook"
          }
        ]
      }
    ]
  }
}
```

Codex matches `apply_patch`, the tool it makes every edit with, and runs a project's hooks only once you trust them: review pawl's in Codex's `/hooks`. Copilot runs its hooks after every tool, so pawl skips the tools that edit nothing. Under Cursor the edit hook only fixes, and what is left reaches the agent from the stop hook, which Cursor sends as the next message.

When part of the check cannot run, such as an engine that is not installed, the hooks tell you and not the agent: they print the problem and exit with 1, which the agent's tool shows you and goes past. An agent told that Biome is missing would go and install it.

### Why `npx --no`

A plain `npx pawl` runs the copy of `@santi020k/pawl` your project installed. When there is none, as in a fresh clone before the install, npx looks on npm for a package called `pawl`, and that name belongs to someone else. In a hook, an agent's shell or CI nobody can answer npx's question, and npm then installs it without asking. With `--no`, npx runs your copy or fails. Everything pawl writes uses it: the agent hooks, the instructions and the skill, the pre-commit hook, the editor tasks and the workflow.

Older versions of pawl wrote other commands: `npx pawl check --changed --format agent` for Claude Code, `npx pawl fix --changed` for Cursor, and `npx pawl fix --hook` for every agent. Running `init --agents` again swaps them for `npx --no pawl fix --hook` in place and adds the stop hook. `init --hooks` does the same for a pre-commit line pawl wrote, and `init` for the editor tasks.

### Instructions every agent reads

Pawl writes instructions into `AGENTS.md` between `<!-- pawl:start -->` and `<!-- pawl:end -->` markers, so running `init` again updates its block and leaves the rest of the file alone:

```md title="AGENTS.md"
## Code quality

This repo uses pawl. After editing code, run:

    npx --no pawl check --changed --format agent

It prints one JSON line per problem, each with a `fix`. No output means there is nothing to do.
Run `npx --no pawl fix` to apply formatting and safe fixes. If npx cannot find pawl, install the
project's dependencies: the package is `@santi020k/pawl`, not `pawl`.

Do not silence a problem with a disable comment (`biome-ignore`, `eslint-disable`, `@ts-ignore`).
New ones fail the check. Fix the code instead. Do not run `pawl baseline` to make findings go
away either: it accepts them as they are, and that is for a person to decide.
```

Codex, Copilot, Cursor and most other agents read `AGENTS.md` on their own. Two need a pointer:

- **Claude Code** reads `CLAUDE.md`, not `AGENTS.md`. Pawl adds `@AGENTS.md` to the end of your `CLAUDE.md`, or `@../AGENTS.md` to `.claude/CLAUDE.md`, so Claude Code loads it. Without either, it writes a `CLAUDE.md` that only imports `AGENTS.md`. A `CLAUDE.md` that already imports it, or is a link to it, is left alone.
- **Gemini CLI** reads `GEMINI.md` unless its settings name other files. In a repo with a `.gemini` folder, pawl adds `AGENTS.md` to `context.fileName` in `.gemini/settings.json`, after the files it already lists.

### A skill

Pawl writes a skill, the same file in `.claude/skills/pawl/SKILL.md` for Claude Code and in `.agents/skills/pawl/SKILL.md`, where Codex and Copilot look. An agent loads it when it needs it: what to run after an edit, what the stop hook asks of it, how to read the findings and the exit codes, how to look up a rule with `pawl explain`, and what not to do, such as adding a disable comment or running `pawl baseline`. Running `init --agents` again updates pawl's copy. To keep a version of your own, delete the line that says pawl wrote it.

## The hook from your own setup

`--hook` works in any agent's post-edit hook, not only the ones `init` writes. It reads the file paths Claude Code, Codex, Copilot, VS Code, Cursor and Windsurf send, and answers each in its own shape: `hookSpecificOutput.additionalContext` for a `PostToolUse` hook, `additionalContext` for Copilot, nothing for Cursor. A file outside the project, a file that is gone, and a payload pawl cannot read all mean nothing to do. `pawl check --hook` reports without fixing.

The same command in a stop hook reads the stop instead: `Stop` from Claude Code, Codex and VS Code, Copilot's `agentStop` and Cursor's `stop`. It answers `{ "decision": "block", "reason": ... }`, or Cursor's `followup_message`, and lets the agent finish when Cursor says the turn was cancelled. It knows a session by the `session_id`, `sessionId` or `conversation_id` the payloads carry, and it checks only the files the edit hook recorded for that session, in your system's temporary folder. Without an edit hook, it has nothing to check.

## Running init under an agent

`init` offers a menu in a terminal. In CI or under a coding agent it uses `auto`, so an agent can set up a repo without getting stuck on a prompt. Add `--yes` to accept the plan without asking.
