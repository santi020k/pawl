# @santi020k/pawl

## 0.2.0

### Minor Changes

- [`902c0e8`](https://github.com/santi020k/pawl/commit/902c0e89a405d8bc63f6c37e00caeb0c8a7db8b5) Thanks [@santi020k](https://github.com/santi020k)! - The API adds `loadProject`, which loads the policy, detects the project and works out its tools in one call, and `explainRule`, which returns what `pawl explain` prints for a rule.

  Breaking: `usesReact` and `BIOME_REACT_PRESET` are removed. Use `technologies(detection).includes('react')` and `biomeTechPreset('react')`.

- [`d56ff9a`](https://github.com/santi020k/pawl/commit/d56ff9a20e13ae0ae935ab3d1ec2b22e2491ce8d) Thanks [@santi020k](https://github.com/santi020k)! - The policy takes `biomeOptions`: rule options in Biome's own shape, by the same names as `rules`, at the top level and in `overrides`. They replace the options the standard gives a rule, and reach `biome:group/name` rules too. Until now only ESLint and Oxlint took options from the policy.

- [`f2e014b`](https://github.com/santi020k/pawl/commit/f2e014bc3fde04cd24a005e59fb0e8cded78feed) Thanks [@santi020k](https://github.com/santi020k)! - `pawl check --since <ref>` and `pawl fix --since <ref>` look only at the files the branch changed since it left `<ref>`, such as `origin/main`: its commits, what is not committed yet, and untracked files. It is the pull request mode for CI, and a way to bring a large repo under the standard one pull request at a time. When git does not know the ref, or the clone is too shallow to join it to the branch, the check stops with exit code 2 and the new `since-unresolved` setup problem. The library takes the same as `since` in the options of `check`.

- [`9c7b147`](https://github.com/santi020k/pawl/commit/9c7b14732e004353699dc2663684ca96941a0151) Thanks [@santi020k](https://github.com/santi020k)! - `pawl doctor` reports the same setup problems as `pawl check`. A package's `biome.json`, or one of pawl's own Biome rule files, that is missing or out of date now shows up in the doctor too, and a missing engine or a loosened locked rule reads the same in both. A project that uses Biome without having it installed gets the new blocking `biome-missing` setup problem instead of `engine-failed`. In `pawl doctor --format json`, ESLint now comes before Prettier, the order the engines run in.

- [`ce0d4c4`](https://github.com/santi020k/pawl/commit/ce0d4c4e54291620214c02eb636016d170384ac5) Thanks [@santi020k](https://github.com/santi020k)! - `pawl explain` knows the names pawl gives a finding: its own, such as `pawl/sort-package-json` and `eslint:parse`, and those of an engine's own rules, such as `biome:style/noDefaultExport`, which it links to the engine's page for. `pawl explain pawl/ai-keys` shows what a guard refuses, the level it runs at and whether it is on in the project, and `pawl explain pawl/sort-package-json` says how to fix that one. These names used to get "not in the pawl catalog" and exit code 1, though pawl's own output had printed them. The names the output prints for a rule of the catalog, such as `oxlint:typescript/no-floating-promises` or Oxlint's `typescript/no-floating-promises`, lead to that rule.

- [`79163e0`](https://github.com/santi020k/pawl/commit/79163e02c70b797ab44b3049c85d26a923fea525) Thanks [@santi020k](https://github.com/santi020k)! - The Zod guard also refuses `z.union()` of string `z.literal()` values in place of `z.enum()`, and a new opt-in guard, `zod-meta`, refuses `.describe()` in place of Zod 4's `.meta()`: `pawl add zod-meta`. It is not on by itself because Zod 3, and the tool schemas of the AI SDK, write `.describe()`. The Testing Library guard also refuses queries taken from `render()` in place of `screen`, and a new guard, `testing-library-find-by`, warns about `waitFor()` around a `getBy` or `queryBy` query. They need no plugin and run in Biome, Oxlint's imports aside, and in ESLint. The matching `eslint-plugin-zod` and `eslint-plugin-testing-library` rules are off in the packs, so nothing is reported twice.

- [`a075b7c`](https://github.com/santi020k/pawl/commit/a075b7c21e2e44d439c721699b553b7f8fbfb5c8) Thanks [@santi020k](https://github.com/santi020k)! - In a policy's `ignore` and in the `files` of an override, `[` and `]` are the characters themselves, so `src/app/[slug]` names that route folder in every engine. Before, Biome refused the whole config, and ESLint and Oxlint read the brackets as a character class.

  Breaking: a policy that used a class there, such as `**/*.min.[jc]s`, has to list the names now, as `**/*.min.js` and `**/*.min.cs`: `pawl doctor` names such a pattern when its brackets match no file, and `pawl migrate` lists out the classes of the ignore patterns it copies from ESLint.

  A `.gitignore` line with a leading slash, such as `/build`, skips only that path at the root, as git reads it; pawl's own checks and ESLint used to skip every `build` folder. Character classes in `.gitignore` lines, such as `*.py[cod]` and `[[:digit:]]`, are read as git reads them, and a line git cannot match anything with, such as one with a `[` that does not close, matches nothing. Braces in those patterns, as in `**/*.{gen,auto}.ts`, now work the same in every engine: pawl lists them out, where before Biome read them as a glob and ESLint as the characters themselves.

- [`6a78bea`](https://github.com/santi020k/pawl/commit/6a78bea94a45ffaefa8d4d35ad4ad5aaed26c48c) Thanks [@santi020k](https://github.com/santi020k)! - A new Markdown check, `pawl/markdown-no-invalid-label-refs`, finds a reference with only whitespace between its second brackets, such as `[text][ ]`, which CommonMark does not read as a reference. It is an error by default, like the rule of the same name in `@eslint/markdown`, and skips code blocks, code spans, HTML comments and front matter. The rule is off in the `markdown` pack, so nothing is reported twice.

- [`49a50cf`](https://github.com/santi020k/pawl/commit/49a50cf24ba0067fe5a2cdc4c6c03b34ec51e0fc) Thanks [@santi020k](https://github.com/santi020k)! - An override sets the level of pawl's own Docker and Markdown checks for the files it names, as it does for the rules an engine runs. Those checks used to read only the top-level `rules`, so `pawl/markdown-no-duplicate-headings` could not be switched off for a changelog alone.

- [`6662135`](https://github.com/santi020k/pawl/commit/66621353913ee93fe97e01c3f1775e4ba1666076) Thanks [@santi020k](https://github.com/santi020k)! - `pawl init` adds `oxlint-tsgolint` to TypeScript projects that lint with Oxlint, so the rules of the standard that need type information run there too. Type-aware mode now follows `package.json`, as every other tool does, so `.oxlintrc.json` does not change when the install runs. When the package is declared but not installed, `pawl check` stops with the `tsgolint-missing` setup problem and exit code 2, and `pawl doctor` says to install the dependencies. Only the root `package.json` counts, because Oxlint runs at the root and looks for tsgolint from there: when only a workspace package declares it, `pawl doctor` says to add it to the root's devDependencies. `pawl doctor` also checks the installed version against the range pawl works with.

- [`00f5981`](https://github.com/santi020k/pawl/commit/00f5981e815bf7fbc0a65ffa0ab438854e0ffe4a) Thanks [@santi020k](https://github.com/santi020k)! - With Oxlint as the linter, pawl now drives the rules that need type information, such as `@typescript-eslint/no-floating-promises`, when the project depends on `oxlint-tsgolint`. It writes those rules, for TypeScript files only as in ESLint, and `options.typeAware` into `.oxlintrc.json`, and `pawl sync` adds or removes them as the dependency comes and goes. Without the package, pawl leaves them out and `pawl doctor` asks for it. `oxlint-tsgolint` is a new optional peer dependency. ESLint beside Oxlint no longer takes a rule that Oxlint runs with it.

- [`2b9bbeb`](https://github.com/santi020k/pawl/commit/2b9bbeb0652e242269754d1aa611ef22039951a7) Thanks [@santi020k](https://github.com/santi020k)! - Pawl checks the values of a policy, in every layer, as it already checked the names of its options. A level that is not `off`, `warn` or `error`, a string where a list belongs, an override without `files`, an unknown runtime or a pack name pawl does not have now stops the run with exit code 2, and the message names the place and what it takes: `"rules.no-console" is "warning". It must be "off", "warn" or "error".` Until now such a value passed in silence or failed later inside an engine. A policy that relied on a wrong value being ignored has to be corrected.

- [`e78dd2d`](https://github.com/santi020k/pawl/commit/e78dd2df5db9060b42449c6f216c420d592bb1be) Thanks [@santi020k](https://github.com/santi020k)! - The ratchet on disable comments counts Oxlint's own, `oxlint-disable`, `oxlint-disable-line` and `oxlint-disable-next-line`, which got past it until now. It also reads the stylesheets, JSON and GraphQL files Biome lints, and the YAML and TOML files an ESLint pack lints, where a `biome-ignore` or `eslint-disable` comment switched a check off unseen. A repo that already has such comments sees them once as new: run `pawl baseline` after upgrading to record them.

- [`9da886a`](https://github.com/santi020k/pawl/commit/9da886ab57397072491f008dd7a1fcbe60bd75fd) Thanks [@santi020k](https://github.com/santi020k)! - The setup API has one shape for every command. `planInit`, `planAdd`, the new `planSync` and `planMigrate` return plans of `SetupAction`s, and `applyPlan` writes any of them. `pawl sync` itself is built on `planSync`.

  Breaking: `applyInit` is now `applyPlan`, the `InitAction` type is now `SetupAction`, `planAdd` returns a `SetupPlan` (it no longer carries init's `mode`, `engines` and `formatter`), and `planPrettierConfig` is no longer exported: use `planSync`.

### Patch Changes

- [`b23bb6b`](https://github.com/santi020k/pawl/commit/b23bb6bfb0b3ad45e028f09388a1ed40eefcfd48) Thanks [@santi020k](https://github.com/santi020k)! - Five rules of the standard are marked as needing type information, as typescript-eslint defines them: `consistent-type-exports`, `no-deprecated`, `no-unnecessary-type-assertion`, `no-unsafe-return` and `prefer-nullish-coalescing`. ESLint loads type information only when an active rule needs it, so a policy that switched `prefer-optional-chain` off while one of these stayed on gave ESLint a rule it cannot run without types. A test now checks the mark against the rule list of the pinned Oxlint.

- [`fecf643`](https://github.com/santi020k/pawl/commit/fecf64379be4658ff48865a17689707c636a6513) Thanks [@santi020k](https://github.com/santi020k)! - A pnpm workspace whose `packages` list has no indent, or is a flow list such as `[apps/*, packages/*]`, on one line or over several, is read as a monorepo. Pawl saw a single package there, so it missed the technologies of the packages and gave none of them a Biome config of its own. Workspace patterns with a wildcard inside a name, such as `plugins/plugin-*`, with `**` at any depth, with braces or classes, and with a leading `!` are followed as pnpm follows them. The root is never one of the packages, even when the list names `.`.

## 0.1.0

### Minor Changes

- First public release of pawl: one standard for Biome, Oxlint, ESLint and Prettier, with guards for AI SDKs, Docker and Markdown checks, optional packs, a ratchet baseline and agent-friendly output.
- Covers the rules of `@santi020k/eslint-config-basic` without a plugin wherever Biome or Oxlint has one, with guards for Zod, Testing Library and Nuxt, and Markdown checks of pawl's own.
- The standard has 200 rules, including the `jsx-a11y` and `promise` rules that Biome or Oxlint enforce without the plugin. The Stencil pack uses the official `@stencil/eslint-plugin`.
- The policy takes path-scoped `overrides`, a `runtime`, `detect`, `gitignore`, `defaultIgnores` and `maxWarnings`, and refuses unknown keys. A JSON schema ships as `@santi020k/pawl/schema.json`.
- Every engine and pawl's own checks share one ignore list and follow `.gitignore`.
- `pawl doctor --format json` reports the setup and checks Node, Biome and plugin versions; `pawl check --max-warnings <n>` fails on too many warnings.
